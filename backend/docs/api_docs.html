Limen

Inbound
API

Read gates, people and events, create visitors and badges, and open a gate from your own software.

Versionv1
Base URLhttps://SERVER:8443/api/v1
FormatJSON · HTTPS

00Overview

The API is inbound only: your program calls Limen, Limen never calls your systems.

  • Accountswho can use the API
  • Authenticationlogin and token
  • Errorsstatus codes
  • Endpointsgates, people, events, visitors, badges, open
  • Typical flowa complete example
Replace SERVER in every example with the address of your Limen server (shown in your browser, e.g. 192.168.1.16). The server uses HTTPS on port 8443; with the default self-signed certificate, add -k to curl or install the certificate on the client.

01Accounts

API accounts are created by an administrator in System properties → API. Each account has a username and a password. The password is shown once at creation and is stored only as a bcrypt hash.

Full accessEvery account can use the whole API. There are no per-account permissions to manage.
One per programGive each program its own account, so you can revoke one without touching the others.
RevocableAn administrator can revoke an account, issue a new password or delete it. Tokens stop working immediately.

02Authentication

Send the username and password in the JSON body. You get a token valid for 48 hours; when it expires, log in again.

Request
curl -k -X POST https://SERVER:8443/api/v1/auth/token \
  -H "Content-Type: application/json" \
  -d '{"username": "portineria", "password": "YOUR_PASSWORD"}'
Response 200
{ "access_token": "k3J…", "token_type": "bearer",
  "expires_in": 172800, "expires_at": "2026-11-02T10:00:00Z" }

Use the token on every other request:

Authorization: Bearer <access_token>
  • Tokens are random 256-bit values; the server stores only their SHA-256 fingerprint.
  • After 5 wrong attempts in 15 minutes (same client address and username) login answers 429 with a Retry-After header.
  • The server is meant to be reached over HTTPS only, so credentials and tokens are never sent in clear text.

03Errors

Errors have the form {"detail": "message"}.

StatusMeaning
401wrong credentials, or missing / invalid / expired token
404object not found
409conflict (badge already assigned, gate disabled)
422invalid body or parameters
429too many failed logins
503gate device offline, command not sent

04Endpoints

Dates. All date-times are ISO 8601. For people they are local time (no zone); for events they are UTC with a trailing Z.
GET/gates

List of gates. mode is one of normal, scheduled_unlock, maintenance, emergency.

Response 200
[{"id": 1, "name": "Main entrance", "enabled": true, "mode": "normal"}]
GET/people

List of people and visitors.

QueryDescription
qwords matched on first and last name
visitorstrue or false: only visitors, or only people
limitdefault 200, max 1000
Response 200
[{"id": 7, "first_name": "Mario", "last_name": "Rossi", "visitor": true, "active": true,
  "valid_from": null, "valid_until": "2026-11-03T18:00", "badges": ["04A1B2C3"]}]
GET/events

Latest passages, newest first.

QueryDescription
sinceonly events from this UTC date-time on
gate_idonly this gate
limitdefault 100, max 1000

Possible result values: granted, denied_unknown_credential, denied_outside_schedule, denied_no_rule, denied_credential_disabled, denied_credential_expired, denied_anti_passback, denied_gate_disabled, denied_gate_maintenance, denied_gate_not_authorized, denied_rule_disabled, denied_data_outdated, door_forced, door_left_open, remote_open, external_open, input_activated, output_triggered.

Response 200
[{"id": 981, "timestamp": "2026-10-30T08:12:44Z", "gate": "Main entrance",
  "result": "granted", "badge": "04A1B2C3", "person_id": 7}]
POST/visitors

Creates a visitor. The expiry valid_until is mandatory and applies to the person and to the badge.

FieldDescription
first_name, last_namerequired
valid_untilrequired, end of validity (local time)
valid_fromoptional, start of validity; default: now
badge_codeoptional, badge to attach right away
curl -k -X POST https://SERVER:8443/api/v1/visitors \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"first_name":"Mario","last_name":"Rossi","valid_until":"2026-11-03T18:00","badge_code":"04A1B2C3"}'

Returns 201 with the person object, or 409 if the badge is already assigned.

A visitor has no access rules until you give them some in the web interface (for example by adding them to a group).
POST/people/{id}/badges

Attaches a badge to a person.

{"code": "04A1B2C3"}

Returns 201 with the person, or 409 if the badge is already assigned.

POST/gates/{id}/open

Sends the open command to the gate. It is fire-and-forget (UDP): 503 if the device is offline.

Response 200
{"gate_id": 1, "sent": true}

05Typical flow

  • POST /auth/token once; keep the token and its expires_at.
  • Call the endpoints with Authorization: Bearer.
  • On 401, log in again and retry once.
Example in Python
import requests

BASE = "https://SERVER:8443/api/v1"
s = requests.Session(); s.verify = False   # self-signed certificate: better, pass the certificate path

r = s.post(f"{BASE}/auth/token", json={"username": "portineria", "password": "…"})
token = r.json()["access_token"]
s.headers["Authorization"] = f"Bearer {token}"

v = s.post(f"{BASE}/visitors", json={"first_name": "Mario", "last_name": "Rossi", "valid_until": "2026-11-03T18:00"}).json()
s.post(f"{BASE}/people/{v['id']}/badges", json={"code": "04A1B2C3"})
